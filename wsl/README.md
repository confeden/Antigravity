# Antigravity и WSL

В обычном окне анлокера выберите настройки Windows, включите **«применить и для WSL»** и отметьте обнаруженные дистрибутивы. Нажмите обычную кнопку применения; когда требуется разрешение администратора, подтвердите запрос Windows. Затем используйте встроенный режим WSL в Antigravity обычным образом. Состояние и ошибки отображаются в анлокере; незавершённую операцию нельзя считать успешной.

Отключите выбранную настройку и примените изменения для отката. Восстановление зависит от сохранённого состояния установки и проверки текущих файлов; при конфликте или незавершённой операции сохраните данные и разберите показанную ошибку, не заменяя файлы вручную. Обновление Antigravity может потребовать повторного применения; совместимость новых версий заранее не гарантируется.

Проверенный Desktop — 2.28.2. Linux-помощнику нужны x86-64, glibc не ниже 2.34, системный загрузчик и `libgcc_s.so.1`. Конкретная сборка может потребовать более новую glibc в зависимости от среды сборки; проверяйте совместимость с целевым дистрибутивом. Неподдерживаемая среда и конфликт файлов приводят к ошибке. Доступ к шлюзу может охватывать процессы с тем же наблюдаемым исходным IP, включая другие дистрибутивы и контейнеры; учитывайте это при разрешении доступа.

## Сборка пакета

Собранный помощник и файл его хеша не входят в исходный репозиторий. Сначала соберите помощник из корня исходного дерева в Linux x86-64 с установленными Rust и Cargo, C-компилятором и системными библиотеками, совместимыми с целевой glibc. Этот рецепт ещё требует проверки в целевой Linux-среде:

```sh
cargo build --release --locked --bin ag_wsl_launch
sha256sum target/release/ag_wsl_launch
```

Сохраните только полученный шестнадцатеричный SHA-256 в `helper.sha256` и скопируйте собранный `ag_wsl_launch` в пакет. На Windows с Rust и целевой сборкой MSVC задайте этот же проверенный хеш до сборки:

```powershell
$env:AG_WSL_HELPER_SHA256 = '<sha256-собранного-помощника>'
cargo build --release --locked --bin ag_unlocker
```

Рядом с `ag_unlocker.exe` разместите `ag_wsl_launch`, `helper.sha256` и исходный `wsl/install-helper.sh`. Компиляция связывает доверенный хеш с Windows-программой; изменяемый манифест сам по себе не подтверждает произвольный помощник. Без входного хеша пакет считается неполным для WSL. После сборки проверьте хеши конечных файлов пакета и выполните проверки на целевых системах; рецепт не является свидетельством их прохождения.

Для публично распространяемых двоичных файлов также устраните локальные пути исходной машины из выходных данных сборки и проверьте результат. Rust поддерживает [сопоставление путей исходников](https://doc.rust-lang.org/rustc/command-line-arguments.html#--remap-path-prefix-remap-source-names-in-output); одно указание параметра не заменяет проверку итоговых файлов.

## Terms and Abbreviations

WSL — Windows Subsystem for Linux, подсистема Linux в Windows. SHA-256 — криптографический хеш содержимого. MSVC — компилятор Microsoft Visual C++.
